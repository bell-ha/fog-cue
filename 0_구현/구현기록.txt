보행동결 자극 시스템 — 구현 기록 (2026-11-09)

아이디어 발표(1_아이디어발표의 pptx)와 비교한 기록이다.
숫자는 본인이 기기를 허리에 차고 잰 기록에서 나왔다. 환자 데이터가 아니다.
자세한 수치는 걷기와_동결흉내_차이.txt.


1 ---------------- 지금까지 한 것
* 개발 환경: 맥북 + VS Code + arduino-cli. ESP32와 MPU-6050(가속도 센서) 연결 확인
* 센서 샘플레이트 실측 62.0~62.4 Hz (설계 62.5 Hz, 오차 1% 이내)
* 1단계 걸음 세기 — 허리 고정 걷기 2번(각 32걸음), 놓침 0 · 중복 0
* 3단계 동결 판정 — 기준을 새로 정해 펌웨어에 넣었다. 기록으로 검증한 결과:

      판정 방식              잡힌 흉내   판정까지   걷기에서 잘못 울림
      FI만 (아이디어)         4 / 7        4.6초      0번
      규칙성 + FI (지금)      7 / 7        3.0초      0번

* 부저 — 걷던 빠르기에 맞춘 박자, 첫 박만 높은 음, 처음엔 작게 시작. 소리 크기 조절
* 택트스위치 — 누르면 박자를 켜고, 다시 누르면 끈다
* 진동 — 박자에 맞춰 떤다(첫 박은 길게). 소리 / 진동 / 둘 다 선택. 둘 다는 진동 0.5초 먼저 (아이디어 발표 10번)
* 설정 기억 — 소리 크기 · 박자 방식이 플래시에 남는다. 껐다 켜도 그대로 (확인함)
* 웹 화면 — 기기 진단 · 실시간 · 측정 · 앱. 소리 크기·박자 빠르기 조절, 어느 화면에서든 소리 끄기.
  소리·진동은 실시간 · 앱 탭에서 시작을 눌렀을 때만 나간다 (다른 화면에서 흔들어도 울리지 않게)
* Wi-Fi — 벨트가 Wi-Fi에 붙어 USB와 같은 줄을 내보내고 같은 명령을 받는다. 웹 화면에서 USB / Wi-Fi를 고른다.
  10초 동안 초당 62.5줄, 빠진 줄 0 (줄 사이 최대 17 ms). 네트워크는 ESP32 코어 0에서 따로 돌려 센서 읽기가 밀리지 않게 했다
* 웹 화면 '앱' 탭 — 착용자 · 보호자 휴대폰 화면 (홈 · 기록 · 설정). 지금 상태 · 걸음 빠르기 · 굳은 횟수 · 기록이 벨트와 이어진다
  알림: 착용자는 박자가 멈춘 뒤 결과와 함께. 보호자는 저녁 요약, 30초 넘게 안 풀리면 바로, 다시 걸으면 한 번 더
  자세한 것은 3_중간피드백발표/앱화면.txt
* 돌아서기 구분 — 자이로를 켜서 세로축으로 도는 빠르기를 잰다. 최근 1초에 20도 넘게 돌았으면 '도는 중'으로 보고,
  그동안과 돌기를 멈춘 뒤 3초는 판정을 미룬다. 돌다 굳으면 몸통 회전이 멈추므로 그때부터 판정이 다시 돈다.
  가만히 둔 벨트에서 회전 0 °/s 근처(영점 자동 보정), 합성 신호로 시간 확인: 도는 걸 0.3초에 알아채고,
  회전이 멈추면 약 3.7초 뒤 판정을 다시 센다. 실제로 돌면서 걸어 본 시험은 아직이다
* 걷기 · 서 있기 · 동결 흉내 기록 (data/raw)
* PC 계산과 기기 계산이 같은지 자동 시험 (소수 넷째 자리까지 일치)


2 ---------------- 전과 다른 것 (아이디어 발표 대비)
* 판정 기준: 3~8 Hz 떨림(FI) 하나 → 걸음 규칙성 + FI + 움직임 세기
  허리에서 흉내 7번 중 3번은 3~8 Hz 떨림이 약해 FI로 안 잡혔다. 걷는 리듬이 무너진 것은 7번 모두 보였다.

      움직임 세기 ≥ 0.005  그리고  ( 걸음 규칙성 < 0.41  또는  FI ≥ 1.5 )  — 2번 연속이면 울림

* 판정 시점: 발이 멈추면 판정 → 걸음과 상관없이 판정
  떠는 동안에도 걸음이 계속 세어져 '멈춤'이 오지 않았다.
* 템포: 직전 케이던스 → 5초 전 케이던스
  판정 무렵에는 떨림이 걸음으로 세어져 케이던스가 부푼다 (95~137, 직전 걷기 85~90).
* 끄는 시점: 다시 걸으면 끔 → 판정이 2번 연속 풀리면 끔 (떨기를 멈춘 뒤 2~3초 더 울림)
* 택트스위치: 4단계 → 3단계부터. 판정을 시험하는 동안 잘못 울린 소리를 바로 끄려고 앞당겼다.
* 착용: 허리 고정이 결과를 좌우했다. 손에 들면 손 떨림이 동결처럼 보였다.
* 자이로: 안 씀 → 씀. 돌아설 때 잘못 울리는 것을 막으려고 켰다 (전류 약 3.6 mA 더).
  돌 때 판정을 끄지 않고 미루기만 한다 — 돌아서다 굳는 일이 가장 흔해서, 끄면 정작 그때를 놓친다.


3 ---------------- 구현할 것
* 실시간 판정 시험 (웹 화면 '실시간' 탭)
* 돌아서기 시험 — 측정 탭 '방향 전환'으로 돌 때 M을 누르며 2분 기록. 돌 때 울리지 않는지,
  돌다 멈춰 떨면 울리는지 본다. 20도 · 3초는 출발값이라 기록을 보고 고친다
* 넘어짐 감지 — 넘어진 채 바닥에 있는 자세가 이어지면 알리고, 30초 안에 버튼으로 취소. 취소해도 일어나지 못하면 다시 알림
* 휴대폰 앱 · 서버 — 지금은 같은 공유기에 붙은 컴퓨터 화면까지. 회사에 있는 보호자에게 가려면 서버가 필요하다
* 기록 저장 — 지금은 화면을 새로 고치면 사라진다. 며칠치를 벨트나 서버에 남긴다
* 배터리로 하루 쓰기 (지금은 USB 전원)


4 ---------------- 연결 (배선)
ESP32는 30핀 확장보드에 꽂았다. 확장보드는 핀마다 G · V · S 세 칸이 있고, V 전원 점퍼는 3.3V에 두었다.

    부품                  부품 핀        ESP32 / 확장보드          상태
    MPU-6050 (GY-521)     VCC            3V3                       동작 확인
                          GND            GND
                          SDA            D21 (GPIO21)
                          SCL            D22 (GPIO22)
                          AD0            연결 안 함 → 주소 0x68
    수동 부저             + (긴 다리)     D25 줄의 S (GPIO25)       동작 확인
                          − (짧은 다리)   D25 줄의 G
    택트스위치            한쪽 다리       D14 줄의 S (GPIO14)       동작 확인
                          다른 쪽 다리    D14 줄의 G
    진동 모터 모듈 (3핀)   IN             D26 줄의 S (GPIO26)       동작 확인
                          VCC            D26 줄의 V (3.3V)
                          GND            D26 줄의 G
    맥북                  USB-C          ESP32 USB 단자            /dev/cu.usbserial-210 (USB 칩 CH340)

* SDA와 SCL을 바꿔 꽂으면 센서가 안 보인다 (처음에 실제로 그랬다).
* 전원은 3V3에 꽂는다. VIN(5V)이 아니다.
